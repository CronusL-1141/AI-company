# Codex 请求计价证据修复

## 已确认问题

本机截图区间的 1649 条已计价请求中，739 条缺少 service_tier，其中 730 条来自子会话；旧解析器直接按 Standard 计价且丢掉这个假设。缓存分类与 Fast/长上下文费率公式正确。另有 7 条独立 compact 请求缺模型，其 response_id 与 compacted.compaction_response_id 一一对应，但没有同 turn_id 的模型记录。

## 修复边界

- 当前线程配置可查看，但不作为历史执行配置。模型使用请求原始字段或同 turn_id 的上下文；档位使用原始请求、同 turn 上下文或此前生效的线程设置。明确 null 清空证据，不能继续使用旧值。
- 每个计价条目保留模型、档位来源。缺档位仍可提供 Standard API 等值估算，但明确标为假设；不能宣称该区间计价完整。不统一乘 2，不重置用户统计起点，不删除已有金额。
- 当前周期向 API/UI 提供带假设的已计价请求数，替换误导性的“全部按日志档位”副标题，提供中英文说明。旧记录的 standard 缺乏来源时视为未核实，不能通过新代码替旧证据背书。
- 原生用量 journal 保存已存在的 service_tier 及来源，避免今后继续丢字段。保留输入、缓存读取、缓存写入、输出的独立计数；推理输出已经包含在输出内，不重复加钱。
- 真实无法恢复的 compact 模型保持未知。原始观测和历史报价不改写；有明确原始证据的后续纠正须单独可审计，不用当前配置批量倒填。

## 验收

覆盖子会话、换模型/换档、显式 null、错位 turn、未知档位、重复响应及归档、缓存读取/写入、Fast 与长上下文叠加；跨保存/重开库核对来源和金额。原生配置可读不等于历史计价已恢复，最终报告应列剩余缺口。

## 09-23 接管复核

补齐无法识别轮次的边界：见过缺少 turn_id 的 turn_context 后，不得再把旧线程档位或随后出现的设置当作该请求证据。完整扫描器保留是否见过 turn 的状态；持久化 cursor 用 true / false / null 区分已见、明确未见、旧记录未知，未知保持保守。回归覆盖显式 null、缺字段、后置设置与旧 cursor 跨 SQLite 重开；不改写历史观测或报价。
