# 任务生命周期与外部执行用量契约

本文件描述任务管理、外部执行证据以及两者的边界。实现入口为src/aiteam/task_management.py、src/aiteam/services/external_exec.py与相应API/MCP；参数示例见task-wall-mcp-guide.md和src/aiteam/data/USAGE.external-exec.md。

## 任务关系与状态

项目/团队创建和更新支持同项目parent_id与depends_on。父子仅一层；拒绝自指、环、跨项目关系，以及向已完成父任务新挂子任务。parent表达范围归属，dependency表达前置顺序；标题和标签不产生结构关系。

未开始任务可按未完成依赖推导为blocked。auto_start请求运行状态但不派工；没有显式status=running时，不能实际开始则返回真实阻塞状态。创建和更新显式请求status=running时，未完成依赖或未清除等待都返回409，即使同时传入auto_start也不能吞掉明确请求。已经running的任务在编辑无关字段时保留其执行状态；新增依赖有冲突时须明确拒绝，不能返回成功并悄悄丢掉运行状态。需要暂停时由调用者明确记录，不从agent活动推测。

waiting_on只表示user或agent的明确等待；任务前置使用depends_on。新状态记录dependency/manual/waiting原因，依赖完成只自动解除dependency阻塞。旧blocked无已知原因时保持原状并给出提示，不推断历史原因。

完成检查未完成依赖、明确等待和未关子任务。failed子任务仍属于未关事项；不能为了完成父任务伪称子任务成功，应解决失败后完成，或明确调整任务范围/关系。普通completed更新与专用complete共用事务，检查、下游解锁及审计一起提交。重复完成可补偿下游解锁，保留原始完成时间；历史completed但时间未知的记录继续保留未知，不能通过编辑补上当前时间。

## 编辑与并发

省略字段保持原值；description、result、status_note及assigned_to可显式清空，title不能为空，priority/horizon/status必须是合法枚举。HTTP的parent_id=null、waiting_on=null分别解绑父任务和解除等待；MCP使用parent_id=""、waiting_on={}。数组使用[]清空。

管理字段存入独立config子键，不改冻结的config.memo。每次有效更新递增revision，包括内部状态变化和依赖解锁。expected_revision不匹配返回结构化409，包含current_revision/current_task；省略期望版本保留旧调用兼容，但不能提供版本冲突保护。内部普通config写入不能用旧副本覆盖管理服务的新字段。

前端保留固定的编辑初始快照，只提交实际修改字段。冲突重试展示最新内容并明确指出本次将覆盖哪些字段，其他会话修改的未编辑字段不随重试回滚。

## 批量与可见性

批量创建为1-100条任务，每条有唯一key；parent_id/depends_on接受同批@key或真实UUID。先校验完整关系图和最终状态，再同事务创建；输入顺序不影响结果。idempotency_key上限200字符，与存储声明一致；相同键和参数重放原结果，不同参数冲突。

任务墙和digest的数量统计保持顶层任务口径。等用户事项单列，包括实际等待的子任务及其父任务身份；父卡片可提示等待中的子任务，不把子任务的等待写成父任务自己的waiting_on。执行者停止是提示，不自动改变任务状态。

写回执支持compact/all，默认all保留兼容。精简回执也保留实际状态、关系、revision、错误和警告。查询与写入结果不能冒充真实执行证明。

## 外部执行证据

外部执行通过显式CLI入口接入，不修改全局宿主配置或拦截已有直接调用。适配器强制原生JSON事件输出并透传stdout/stdin，记录调用、原生线程、明确项目/任务归属、时间与状态；未能证明的账号、provider、model和tier保持未知。

只持久化白名单计数与元数据，不保存prompt、代码、工具输出、原始错误正文或完整stdout。原生中间error事件只表示发生过错误，最终回合事件与进程退出状态决定终态。适配器中断先冻结经身份核对、允许清理的执行进程，再强制终止，不运行原生退出处理器或保留软停窗口。退出码保留真实原生子进程结果，不能借监督进程的退出码代填。终态之后拒绝新增回执，完全相同的既有回执仍可幂等重放。

清理完成前保留直接子进程的PID所有权：观察退出不能提前回收；已经回收的PID不得再用于树发现或信号。其他进程不能仅凭数字PID/PGID认领，须核对进程出生身份与调用归属。信号前识别共享OS API及其启动过渡形态，保护其整个进程家族，归属不确定时保留并记录未核实；不得对混有受保护进程的组整体发信号。

父子链和会话归属只能覆盖已观察对象，不能证明首次观测前没有双fork或setsid后被收养的后代。因此强制中断即使已停止全部已识别执行进程，也保留process_cleanup_unverified，不宣称任意后代都已退出。冻结必须以快速派生进程的真实场景及撤除冻结后的失败反证验证。监督进程自身被强杀时无法自救；适配器缺少最终原生状态包时保留未知退出码并报告未核实，不伪造完整清理。全局后台补救不属于此入口。

监督进程在清理后重新检查适配器的生命管道，适配器在清理期间死亡时补存中断终态。监督进程已经退出、适配器尚未提交终态之间仍有崩溃窗口：已提交回执保留，但状态可能停在running，不能当作仍在执行或已正常完成的证明。当前没有终态持久化确认协议，不承诺任意时点强杀都能自动补齐终态。

先保存本地证据再上传。API不可达或版本不匹配时允许执行并留待补传；明确的项目/任务关联错误可拒绝启动。已有合法登记的精确重试不因关联项目后来删除而丢失用量。已发生的执行若关联无法成立，必须保留原请求目标与真实用量，通过明确的未关联/隔离状态收敛，不能永久混在网络重试中。

原生输出的累计计数保留来源和累计层级，不冒充逐请求账。未提供counting_level时保持unknown；显式旧turn_aggregate仍兼容，不改历史原账。缺失保持null；原生全零若不能证明来自有效测量，标明证据不确定。恢复线程的调用不得把线程累计值相加成新增用量。缓存属于输入，推理属于输出，不能另加一次。

## 对账与验证

对账仅基于已保存journal、agent身份和外部回执，分开报告来源分母、采样范围、截断与缺口。Codex子agent按自己的线程身份查询证据，不能借root线程掩盖缺失。MCP只返回有硬上限的摘要和样例，详细读取使用有界HTTP接口；大量数据校验不能阻塞API事件循环。

套餐百分比保持原生账户来源。外部最小观察账不与同线程rollout相加，不按当前登录追认历史归属，不自动混入套餐估值。未留任何证据的旧临时执行不可恢复。

验收使用隔离SQLite并跨请求/持久化边界读回；并发测试应包含多写者、状态解锁和版本增长。撤除必要事务锁或版本比较须使对应测试失败。进程故障使用真实信号注入验证子进程退出与账据保存；不能以手动清理孤儿代替退出保证。测试使用执行机器本机时区，结果如实保留失败、跳过和未验证范围。
